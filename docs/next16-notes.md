# Next.js 16.3.5 cheat sheet (App Router, React 19.2, Tailwind 4)

Verified against `node_modules/next/dist/docs/` (paths below are relative to it) and `node_modules/next` source.
If something here conflicts with the bundled docs, the docs win. Re-check after upgrading `next`.

## 1. Breaking changes in 15/16 that affect new code (`01-app/02-guides/upgrading/version-16.md`)

- **Async request APIs only.** Sync access was removed in 16. `cookies()`, `headers()`, `draftMode()` return Promises. `params` (page/layout/route/default/icon/opengraph-image) and `searchParams` (page) are Promises. Always `await` them, or use React `use()` in Client Components.
- **middleware -> proxy.** File `middleware.ts` -> `proxy.ts`. Export `middleware` -> `proxy` (or default export). Config flags renamed: `skipMiddlewareUrlNormalize` -> `skipProxyUrlNormalize`. Proxy runtime is `nodejs` and cannot be configured. Setting `runtime` in proxy throws. `middleware.ts` still works but is deprecated.
- **`next lint` removed.** `next build` no longer lints, and the `eslint` key in next.config was removed. Use `npm run lint` (which is `eslint`) with the flat config in `eslint.config.mjs`.
- **Turbopack is the default** for `next dev` and `next build`, so drop `--turbopack`. Opt out with `--webpack`. A custom `webpack` config makes `next build` fail. Turbopack options live in top-level `turbopack: {}`, no longer `experimental.turbopack`.
- `next dev` outputs to `.next/dev` (it writes PID/port/URL to `.next/dev/lock`). A lockfile blocks a second `next dev` on the same project.
- **Caching APIs:** `revalidateTag(tag)` with one argument is deprecated (TypeScript error), so pass a profile. `updateTag` and `refresh` are new. `cacheLife` and `cacheTag` are stable: import them without the `unstable_` prefix.
- **Removed:** AMP (`next/amp`, `amp` config), `serverRuntimeConfig`/`publicRuntimeConfig` (use env vars; call `await connection()` before reading `process.env` at runtime), `experimental.dynamicIO`/`experimental.useCache` (-> `cacheComponents`), `experimental.ppr` and `experimental_ppr`, `unstable_rootParams` (-> `next/root-params`), the devIndicators options `appIsrStatus`/`buildActivity`/`buildActivityPosition`.
- **Deprecated:** `next/legacy/image`, `images.domains` (use `remotePatterns`), and the `priority` prop on `next/image` (use `preload`).
- Parallel route slots (`@slot`) now **require** a `default.tsx`, otherwise the build fails.
- Next no longer overrides `scroll-behavior: smooth` during navigation. Add `data-scroll-behavior="smooth"` on `<html>` to restore the old behavior.
- Node >= 20.9, TypeScript >= 5.1.

## 2. Pages, layouts, dynamic routes

Global type helpers exist and need **no import**: `PageProps<'/route'>`, `LayoutProps<'/route'>`, `RouteContext<'/route'>`. They are generated by `next dev`, `next build`, or `npx next typegen`; the scaffold's `app/layout.tsx` already uses `LayoutProps<"/">`.

```tsx
// app/products/[id]/page.tsx
import type { Metadata } from 'next'
import { notFound } from 'next/navigation'

export async function generateMetadata({ params }: PageProps<'/products/[id]'>): Promise<Metadata> {
  const { id } = await params
  return { title: `Product ${id}` }
}

export default async function Page({ params, searchParams }: PageProps<'/products/[id]'>) {
  const { id } = await params
  const { sort } = await searchParams      // plain object, NOT URLSearchParams
  const product = await getProduct(id)
  if (!product) notFound()                 // returns never, no `return` needed; narrows type
  return <h1>{product.title}</h1>
}
```

- Manual typing (from page.md): `params: Promise<{ slug: string }>` and `searchParams: Promise<{ [key: string]: string | string[] | undefined }>`. `[...slug]` gives `string[]`; `[[...slug]]` gives `slug?: string[]`.
- Full generateMetadata signature: `generateMetadata({ params, searchParams }, parent: ResolvingMetadata): Promise<Metadata>`. Server Components only. You cannot export both `metadata` and `generateMetadata` from one segment. Don't hand-write `<title>` or `<meta>` in the root layout.
- Layouts get `children` and `params` but **no `searchParams`**, and they don't re-render on navigation. Read the URL in a Client Component (`useSearchParams` / `usePathname`) or in the page.
- `loading.tsx`: no props. It wraps page + nested layouts in `<Suspense>`, but **not** the same-segment layout. Uncached data or `cookies()` in a layout blocks navigation; wrap it in its own `<Suspense>`.
- `not-found.tsx`: no props, a Server Component (can be async). The root `app/not-found.tsx` also handles unmatched URLs.
- `error.tsx` must be `'use client'`. Props in 16.3 are `{ error: Error & { digest?: string }; retry: () => void }`. **`retry()` re-fetches and re-renders** (stable in 16.3). `reset()` still exists but doesn't re-fetch, so prefer `retry`. Errors in the root layout are handled by `app/global-error.tsx`, which must render its own `<html><body>`.
- `notFound()`, `redirect(path, type?)`, `permanentRedirect(path, type?)` all come from `next/navigation` and all **throw**. Never call them inside `try` (or use `unstable_rethrow`), and never in an un-awaited promise. `redirect` gives 307, `permanentRedirect` 308. In a Server Action: a client navigation when JS is loaded, a 303 for no-JS form posts. The default `type` is `push` in Server Actions and `replace` elsewhere. `redirect` can't be called in client event handlers (use `useRouter`).
- `notFound()` after streaming has started (inside Suspense/loading) returns HTTP 200 plus `noindex`. For a real 404, check before anything suspends.
- `route.ts` and `page.tsx` cannot sit in the same segment.

## 3. Server Actions and forms (`02-guides/forms.md`, `02-guides/server-actions.md`)

```ts
// app/actions/cart.ts
'use server'
import { cookies } from 'next/headers'
import { refresh } from 'next/cache'
import { redirect } from 'next/navigation'

export type CartState = { error?: string }

export async function addToCart(prev: CartState, formData: FormData): Promise<CartState> {
  const id = Number(formData.get('productId'))        // FormData values are strings/File/null
  if (!Number.isInteger(id)) return { error: 'Invalid product' }  // expected errors = return values, not throw
  // auth + ownership checks here: actions are public POST endpoints
  await db.addItem(/* cart id from (await cookies()).get('cart')?.value */ id)
  refresh()                                            // re-render current route in the same response
  return {}
}
```

```tsx
// app/components/add-to-cart.tsx
'use client'
import { useActionState } from 'react'        // NOT react-dom, NOT useFormState
import { useFormStatus } from 'react-dom'
import { addToCart } from '@/app/actions/cart'

function Submit() {                             // useFormStatus must be in a CHILD of <form>
  const { pending } = useFormStatus()
  return <button disabled={pending}>Add to cart</button>
}
export function AddToCart({ productId }: { productId: number }) {
  const [state, formAction, pending] = useActionState(addToCart, {})
  return (
    <form action={formAction}>
      <input type="hidden" name="productId" value={productId} />
      <Submit />
      {state.error && <p aria-live="polite">{state.error}</p>}
    </form>
  )
}
```

- `useActionState` type (@types/react): `useActionState<State, Payload>(action: (state: Awaited<State>, payload: Payload) => State | Promise<State>, initialState: Awaited<State>, permalink?: string): [state, dispatch, isPending]`. With it, the action's first arg becomes `prevState` and `formData` is second.
- `useFormStatus(): { pending, data, method, action }`.
- `'use server'` either at the top of a file (every export is an action) or as the first line of an async function inside a Server Component. You **cannot define** actions in Client Components; import them from a `'use server'` file or pass them as props.
- Extra args: `action.bind(null, id)` gives the action `(id, formData)`. Works in Server and Client Components and keeps progressive enhancement. Hidden inputs are the alternative.
- **Progressive enhancement:** a `<form action={serverAction}>` rendered by a Server Component submits without JS. Forms in Client Components queue submissions until hydration.
- `Object.fromEntries(formData)` includes extra `$ACTION_*` keys, so pick fields explicitly.
- Put `revalidatePath`/`updateTag` **before** `redirect()`, because code after redirect never runs.
- The client dispatches actions **one at a time**, so don't `Promise.all` actions. Default body limit is 1MB: `experimental.serverActions.bodySizeLimit` (it lives in `ExperimentalConfig` in the 16.3.5 types).
- Pending UI without a form: `startTransition(() => action())` or `useTransition`. Optimistic UI: `useOptimistic`.

## 4. Caching and revalidation

- **`cacheComponents` defaults to `false`** (`dist/server/config-shared.js`). Unless we enable it, the "previous model" applies (`02-guides/caching-without-cache-components.md`):
  - Prerendering (static) is the default for routes that use no Request-time APIs (`cookies`, `headers`, `searchParams`, `connection()`). A DB-reading page without those is rendered **at build time**. Call `await connection()` (from `next/server`) to force request-time rendering.
  - `fetch` is **not cached** by default (`{ cache: 'force-cache' }` or `next: { revalidate, tags }` opt in). For non-fetch caching use `unstable_cache(fn, keyParts, { tags, revalidate })`, and use React `cache()` to dedupe within a render. Segment config `dynamic`, `revalidate`, and `fetchCache` still work.
  - In dev, pages are always rendered on demand, so static-vs-dynamic bugs show up only in `next build && next start`.
- **With `cacheComponents: true`:** data is dynamic by default and PPR is on. `'use cache'` (file, function, or component level) with `cacheLife(profile)` and `cacheTag(...tags)` from `next/cache`. Uncached data or runtime APIs outside `<Suspense>` produce a build error. `'use cache'` scopes **cannot call `cookies()`/`headers()`/`searchParams`** (even transitively). Read them outside and pass the values in. Route segment configs like `dynamic`/`revalidate` belong to the old model (see `02-guides/migrating-to-cache-components.md`). cacheLife profiles: `default, seconds, minutes, hours, days, weeks, max`.
- Exact signatures (`dist/server/web/spec-extension/revalidate.d.ts`), all imported from `next/cache`:
  - `revalidatePath(originalPath: string, type?: 'layout' | 'page')`: allowed in Server Actions and Route Handlers. A pattern with a dynamic segment needs `type`: `revalidatePath('/products/[id]', 'page')`. `revalidatePath('/', 'layout')` invalidates everything.
  - `revalidateTag(tag: string, profile: string | { expire?: number })`: allowed in Server Actions and Route Handlers. With `'max'` it's stale-while-revalidate and does **not** re-render in the action response. `{ expire: 0 }` expires immediately (use it in Route Handlers/webhooks).
  - `updateTag(tag: string)`: **Server Actions only** (throws elsewhere). Expires immediately, for read-your-own-writes.
  - `refresh(): void`: **Server Actions only**. Re-renders the current route's RSC payload without invalidating cached data.
- **Fresh header cart count after add-to-cart.** An action re-renders the current route in the same response if it calls `updateTag`, `revalidatePath`, `refresh`, or `redirect`, **or sets/deletes a cookie**. Otherwise only the return value comes back.
  - Cart data uncached (plain DB read in a layout that also reads `cookies()`): call `refresh()`. The upgrade guide uses exactly this for a "count displayed in the header".
  - Cart data cached with a tag: `updateTag('cart')`.
  - Setting the cart cookie in the action already triggers the re-render.
- `router.refresh()` (client) clears the client cache for the current route but does **not** invalidate server caches.
- Nothing mutates during render: Next blocks setting cookies or revalidating inside Server Component render.

## 5. cookies() (`03-api-reference/04-functions/cookies.md`)

```ts
import { cookies } from 'next/headers'
const store = await cookies()
store.get('cart')?.value; store.getAll(); store.has('cart')
store.set('cart', id, { httpOnly: true, secure: true, sameSite: 'lax', maxAge: 60 * 60 * 24 * 30, path: '/' })
store.set({ name: 'cart', value: id, httpOnly: true, path: '/' })
store.delete('cart')   // or set('cart', '', ...) / { maxAge: 0 }
```

- Options: `expires` (Date), `maxAge` (seconds), `domain`, `path` (only default: `'/'`), `secure`, `httpOnly`, `sameSite` (`boolean | 'lax' | 'strict' | 'none'`), `priority`, `partitioned`.
- **Reading** works in Server Components, Server Actions, and Route Handlers. **`set`/`delete` only in Server Actions/Functions and Route Handlers**, never during Server Component render (headers are already streaming).
- Reading `cookies()` in a page or layout makes the route dynamic. With cacheComponents, keep it inside `<Suspense>`.
- In proxy.ts use `request.cookies.get(name)` and `NextResponse.next().cookies.set(...)`.

## 6. Route handlers (`03-api-reference/03-file-conventions/route.md`)

```ts
// app/api/products/[id]/route.ts
import type { NextRequest } from 'next/server'
export async function GET(request: NextRequest, ctx: RouteContext<'/api/products/[id]'>) {
  const { id } = await ctx.params                       // or { params }: { params: Promise<{ id: string }> }
  const q = request.nextUrl.searchParams.get('q')
  return Response.json({ id, q })
}
export async function POST(request: Request) { const body = await request.json(); return Response.json(body, { status: 201 }) }
```

- Methods: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS (OPTIONS is auto-implemented if missing). Unsupported methods return 405.
- Not cached by default. Only GET can opt in (`export const dynamic = 'force-static'` in the old model).
- `cookies()` (read/set/delete), `headers()` (read-only), `redirect()`, and `notFound()` work here. `updateTag`/`refresh` throw here, so use `revalidateTag(tag, 'max' | { expire: 0 })`.

## 7. proxy.ts (`03-api-reference/03-file-conventions/proxy.md`, `02-guides/authentication.md`)

```ts
// proxy.ts at project root (same level as app/)
import { NextResponse, type NextRequest } from 'next/server'
export function proxy(request: NextRequest) {
  if (!request.cookies.get('session')?.value) return NextResponse.redirect(new URL('/login', request.url))
}
export const config = { matcher: ['/((?!api|_next/static|_next/image|favicon.ico|.*\\.png$).*)'] }
```

- Signature: `(request: NextRequest, event: NextFetchEvent)`, or `export const proxy: NextProxy = ...`. Exactly one proxy function per project. Matcher values must be static constants. Matcher entries can be objects `{ source, has, missing, locale }`.
- With no matcher it runs on **every** request, including `_next/static`, `_next/image`, and `public/`.
- Auth guidance from the docs: proxy is for **optimistic** checks only (read the session cookie, redirect). **No DB calls** (it runs on prefetches too). It is "not a full session management or authorization solution". Do real checks near the data (DAL with `import 'server-only'`, in pages and in **every** Server Action and Route Handler). Server Actions are POSTs to the page route, so a matcher that excludes a path also skips its actions.
- `fetch` cache options have no effect in proxy. For simple static redirects prefer `redirects()` in next.config.

## 8. Images (`03-api-reference/02-components/image.md`)

```ts
images: {
  remotePatterns: [{ protocol: 'https', hostname: 'cdn.dummyjson.com', port: '', pathname: '/product-images/**', search: '' }],
  // or: remotePatterns: [new URL('https://cdn.dummyjson.com/product-images/**')]
}
```

- Our data uses `https://cdn.dummyjson.com/product-images/...` (plus `/public/qr-code.png`). Unmatched URLs return 400.
- Remote `src` needs `width` + `height`, or `fill` (with a sized, positioned parent) and `sizes`.
- 16 defaults:
  - `qualities: [75]` (other `quality` values snap to the closest allowed one).
  - `minimumCacheTTL` 4h (was 60s).
  - `16` removed from `imageSizes`.
  - `maximumRedirects: 3`.
  - Local IPs are blocked unless `dangerouslyAllowLocalIP`.
  - Local `src` with a query string requires `localPatterns` with `search`.
- `priority` is deprecated. Use `preload` (docs: usually prefer `loading="eager"` or `fetchPriority="high"`).
- Plain `<img>`: `@next/next/no-img-element` is **`warn`**, even in `core-web-vitals`, so lint still passes. Silence it per line with `{/* eslint-disable-next-line @next/next/no-img-element */}`.

- Other options: `typedRoutes: true` (typed `Link` href and `router.push`, now top-level), `reactCompiler: true` (needs `babel-plugin-react-compiler`), `cacheComponents: true` (a real model change, not a flag flip).

## 10. Client components

- `'use client'` goes at the top of the file, before imports. It's only needed on the entry file imported by a Server Component. Props must be serializable (no functions, except Server Actions). Client Components can't be `async` (lint rule `no-async-client-component`). Context providers must be Client Components; render them as deep as possible.
- From `next/navigation` (not `next/router`):
  - `useRouter()`: `push(href, { scroll })`, `replace`, `refresh()`, `prefetch`, `back`, `forward`.
  - `usePathname(): string`.
  - `useSearchParams()`: a read-only `URLSearchParams`.
  - `useParams()`.
- **`useSearchParams` in a prerendered route must sit under `<Suspense>`**, or `next build` fails ("Missing Suspense boundary with useSearchParams"). **Dev does not catch this.** In a page, prefer reading the `searchParams` prop and passing values down. With `cacheComponents`, `usePathname` also needs Suspense on routes with dynamic params not covered by `generateStaticParams`.
- Mark server-only modules (DB access) with `import 'server-only'`. Only `NEXT_PUBLIC_*` env vars reach the client.

## 11. Tailwind 4 in this scaffold

- There is no `tailwind.config.js`. `postcss.config.mjs` uses `@tailwindcss/postcss` (tailwindcss 4.3.3). `app/globals.css` starts with `@import "tailwindcss";` and is imported once in `app/layout.tsx`.
- Tokens are CSS variables in `@theme`. The namespace determines the utilities (see `node_modules/tailwindcss/theme.css`): `--color-*` gives `bg-*`/`text-*`/`border-*`, and `--font-*` gives `font-*`.

```css
@theme {
  --color-amazon-navy: #131921;   /* bg-amazon-navy */
  --color-amazon-orange: #febd69; /* text-amazon-orange */
}
@theme inline {                    /* inline: value references another CSS var */
  --font-sans: var(--font-geist-sans);   /* next/font `variable` set on <html> in layout.tsx */
}
```

- Scaffold gotcha: `globals.css` sets `body { font-family: Arial, ... }`, which overrides the Geist font. Remove that rule or add `font-sans` to `<body>`. It also flips colors via `prefers-color-scheme: dark`.

## 12. Pitfalls flagged in the bundled docs

- Sync `params`/`searchParams`/`cookies()` access is gone in 16. Always await.
- Wrapping `redirect()`/`notFound()` in `try/catch` swallows them.
- Server Actions and Route Handlers are public endpoints. Authenticate, authorize, and validate in each. Return DTOs, not raw rows.
- Using `revalidateTag(tag, 'max')` and expecting instant UI. Use `updateTag` or `refresh` in actions.
- `cookies()` inside `'use cache'` throws, and on dynamic routes this can pass `next build` and fail at `next start`.
- `useSearchParams` without Suspense works in dev and breaks the build. Always verify with `next build`.
- A proxy with no matcher blocks CSS/JS/images. DB work in proxy is slow. Proxy alone isn't auth.
- Mutations during render (setting cookies, revalidating) are blocked. Use a Server Action.
- The layout's uncached data isn't covered by the same segment's `loading.tsx`.
- After a deploy, clients can hit "Failed to find Server Action". Surface a retry instead of a hard failure.
- `next-env.d.ts` is generated. Never edit it.
- Dev tooling: `next dev` serves an MCP endpoint at `/_next/mcp` (routes, logs, compile issues) and forwards browser console errors to the terminal.
